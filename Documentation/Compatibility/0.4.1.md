# Gnostic 0.4.1 compatibility

This declaration is additive over [0.4.0](0.4.0.md). It changes no wire
contract, no public API, and no dependency requirement: a 0.4.0 peer and a
0.4.1 peer interoperate, and a 0.4.0 consumer recompiles unchanged.

## Package and protocol

- Package version: `0.4.1`.
- Protocol major: `2`, unchanged from 0.4.0. Manifest v2 remains the accepted
  and written schema, and v1 manifest migration is unchanged.
- The bundled Ascendant backend kind is still `positronic` and the bundled
  local Workspace kind is still `echo`.

## Deployment target fix

0.4.0 declared `macOS 26.0` and `iOS 26.0` but called the standard library's
`withTaskCancellationShield`, which is annotated `@available(anyAppleOS 27.0,
*)`. Nine shutdown and cleanup paths across `GnosticCore` and `GnosticCLI`
called it unguarded. Linux builds accepted this because the availability clause
is vacuous there, so the package's own validation never failed; a consumer
building for a 26 deployment target did fail.

Raising a consumer's deployment target does not work around this. Each SwiftPM
target compiles against its own package manifest's minimum, so `GnosticCore`
kept building at `-target …macos26.0` regardless of the consuming package's
declaration.

0.4.1 keeps the declared platforms and routes every call through an internal
`withCancellationShield` wrapper. Above the 27 OS line it forwards to the
standard library shield. Below it, and on non-Apple platforms without the
primitive, it runs the body in an unstructured task, which is not a child of
the caller and therefore does not inherit cancellation. Both paths run the body
in the caller's isolation, and both complete the body before returning, so the
shutdown and cleanup guarantees 0.4.0 documented are unchanged.

A fitness test fails the build if any source outside the wrapper calls
`withTaskCancellationShield` directly, or if the wrapper drops its availability
check.

## Consumer action

A consumer pinned to 0.4.0 that targets the 26 OS line must repin to 0.4.1. No
source change is required.

## Carried forward from 0.4.0

The 0.4.0 declaration remains authoritative for the public consumer clients
(`GnosticTurnClient` and `GnosticWorkspaceClient`) and for the PositronicKit
`6.1.0-rc.1` prerelease pin and its replacement condition. The 0.3.0
declaration remains authoritative for ACP addressing, manifest and migration
behavior, bundled implementations including the Atlas boundary, the intentional
0.2 protocol break, and the removal of Narrative and the direct conversational
CLI.
