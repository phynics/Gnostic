# Gnostic 0.3.0 compatibility

This declaration describes the delivered reset baseline, not a promise of
wire compatibility with earlier pre-1.0 packages.

## Package and protocol

- Package version: `0.3.0`.
- Protocol major: `2`. A peer must advertise and send the supported major on
  every Gnostic object and operation; 0.2 protocol traffic is intentionally
  incompatible.

## Manifest and migration

- Manifest schema `v2` is the accepted and written format.
- A schema `v1` manifest can be decoded and migrated to v2 with its Node,
  Ascendant, Timeline, and Workspace identities preserved. Newly written data
  never emits the v1 `llmProfiles` shape.
- The CLI's `config positronic` convenience targets one existing Positronic
  Ascendant and writes only that Ascendant's backend envelope. There is no
  reusable profile resource or Ascendant profile reference in the live v2
  configuration model; v1 profile records are inlined during migration.

## Bundled implementations

- The bundled Ascendant backend kind is `positronic`; the bundled local
  Workspace kind is `echo`. Embedders and tests may register additional backend
  kinds at the adapter boundary.
- `GnosticPositronicAtlas` provides an optional typed Atlas model and in-memory
  versioned store. It depends on `GnosticCore` and `PositronicKit`; durable
  persistence and host integration remain outside this increment, and
  `GnosticCore` does not depend on Atlas.
- Narrative has been removed from `GnosticCore`; the former shipped runner
  fixture is not part of the product. The broker boundary coverage remains
  test-only. [ADR 0004](../Architecture/ADRs/0004-atlas-supersedes-narrative.md)
  records Atlas as the superseding, optional architecture for a later
  increment.

## Intentional 0.2 breaks

0.2 clients and advertisements do not interoperate with the protocol-major-2
baseline. The old Agent/Chat network contracts and schema-v1-only paths are
retired in favor of Ascendant/Turn and manifest v2. Narrative Core APIs and
the old narrative fixture checks are also retired; callers that need continuity
must wait for or adopt the optional Atlas boundary.

The former direct conversational CLI is also removed. `gnostic acp` is the
user-facing interaction layer. `gnostic inspect` lists and inspects advertised
objects. `gnostic serve` hosts the network operations used by ACP and other
clients.
