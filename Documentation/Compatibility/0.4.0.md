# Gnostic 0.4.0 compatibility

This declaration is additive over
[0.3.0](0.3.0.md). It changes no wire contract: a 0.3.0 peer and a 0.4.0 peer
interoperate. It adds a public consumer client surface and records the
dependency exception this package is released under.

## Package and protocol

- Package version: `0.4.0`.
- Protocol major: `2`, unchanged from 0.3.0. Manifest v2 remains the accepted
  and written schema, and v1 manifest migration is unchanged.
- The bundled Ascendant backend kind is still `positronic` and the bundled
  local Workspace kind is still `echo`.

## Public consumer clients

`GnosticConsumerSession` now vends two clients over its own connection. Neither
opens a second transport, hosts a Node, nor advertises, and neither exposes a
PositronicKit value across the Core boundary.

- `session.turnClient(timeout:promptTimeout:)` returns a `GnosticTurnClient`
  that runs a Turn, replays it by client turn ID, streams its updates, and
  answers permission requests. Every call resolves the addressed Timeline from
  the catalog and requires its Ascendant to advertise `textTurnInput`. There is
  no `ascendant.turn.cancel` wire operation, so a started Turn cannot be
  stopped; cancelling the Swift `Task` stops only the local wait.
- `session.workspaceClient(timeout:)` returns a `GnosticWorkspaceClient` that
  attaches a discovered Workspace to a Timeline, detaches it, invokes an
  advertised tool over `me.atkn.gnostic.workspace.invoke`, and reports
  attachment intent and effective status. Attach requires explicit caller
  approval and the `workspaceAttachment` capability; invocation requires
  `workspaceToolInvocation`. Attach and detach address the Timeline's serving
  provider; invocation addresses the Workspace's advertising provider.

Both clients are valid only while their session runs. After
`GnosticConsumerSession.stop()` later calls fail by transport timeout.

## Dependency exception

This release pins PositronicKit to the prerelease `6.1.0-rc.1` with an exact
requirement, in place of the released `5.1.0` line. The 6.x API the package
migrated to is published only in that prerelease. A consumer therefore
resolves a PositronicKit prerelease transitively, and cannot combine this
package with a different PositronicKit requirement. Replacement condition: when
upstream releases final `6.1.0`, repin to the released exact version and
refresh `Package.resolved`.

Axoloty stays pinned to the released `0.7.0`.

## Carried forward from 0.3.0

The 0.3.0 declaration remains authoritative for ACP addressing, manifest and
migration behavior, bundled implementations including the Atlas boundary, the
intentional 0.2 protocol break, and the removal of Narrative and the direct
conversational CLI.
