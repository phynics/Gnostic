# Gnostic 0.4.2 compatibility

This declaration is additive over [0.4.1](0.4.1.md). It changes no wire
contract, no public API, and no dependency requirement: a 0.4.1 peer and a
0.4.2 peer interoperate, and a 0.4.1 consumer recompiles unchanged.

## Package and protocol

- Package version: `0.4.2`.
- Protocol major: `2`, unchanged from 0.4.0. Manifest v2 remains the accepted
  and written schema, and v1 manifest migration is unchanged.
- The bundled Ascendant backend kind is still `positronic` and the bundled
  local Workspace kind is still `echo`.

## Load-time shield fix

0.4.1 routed cancellation through `withCancellationShield`, which forwarded to
the standard library shield above the 27 OS line. That primitive is
`@_alwaysEmitIntoClient`, so its body is emitted into `GnosticCore` together
with calls to the 27-only concurrency runtime entry points. Those entry points
are strong undefined symbols that the loader resolves when the module loads, not
when the availability branch runs. A module built against the 27 SDK but
deployed to the 26 line therefore fails to load even though the branch is
unreachable, and no runtime availability check can remove an always-emitted
body.

0.4.2 never references the primitive. `withCancellationShield` always runs the
body in an unstructured task, which does not inherit the caller's cancellation
and runs to completion before returning, in the caller's isolation. This is the
fallback 0.4.1 already shipped and tested; it now applies at every OS line. The
declared `macOS 26.0` / `iOS 26.0` platforms are unchanged, and a consumer needs
no source change.

A fitness test fails the build if any source references the 27-only shield again
or reintroduces its availability branch.

## Consumer action

A consumer pinned to 0.4.0 or 0.4.1 that runs on the 26 OS line must repin to
0.4.2. No source change is required.

## Experimental Guile RLM worker

The Guile worker treats `maxOutputBytes` as a hard parent-side frame payload
limit. The parent does not truncate an oversized worker frame: it reports
`outputLimitReached` and terminates the disposable worker. This is intentional;
accepting a partial frame could turn a bounded-output violation into an
ambiguous protocol result.

## Carried forward from 0.4.1

The 0.4.1 declaration remains authoritative for the deployment-target fix. The
0.4.0 declaration remains authoritative for the public consumer clients
(`GnosticTurnClient` and `GnosticWorkspaceClient`) and for the PositronicKit
`6.1.0-rc.1` prerelease pin and its replacement condition. The 0.3.0
declaration remains authoritative for ACP addressing, manifest and migration
behavior, bundled implementations including the Atlas boundary, the intentional
0.2 protocol break, and the removal of Narrative and the direct conversational
CLI.
